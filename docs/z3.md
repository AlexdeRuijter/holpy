# Z3 in holpy

holpy uses the `z3-solver` Python package in two ways.

| Entry point | Used by | Proofs | Z3 context |
|---|---|---|---|
| `z3wrapper.solve(t)` | the `z3` macro and method, `paraverifier` (`basic.py` only imports the module to register the macro) | no, only `unsat` is read | Z3's default context |
| `z3wrapper.solve_and_proof(t)` | `proofrec` (proof reconstruction) | yes | a private `z3.Context(proof=True)` per call |

## Proof generation is not a global setting

Older holpy versions ran `z3.set_param(proof=True)` when `z3wrapper` or `proofrec`
was imported.  That made *every* Z3 call in the process generate proofs, although
`solve` never reads them.  It has been removed, and **new code must not call
`z3.set_param(proof=True)`**: if you need proofs, take them from `solve_and_proof`.
`z3wrapper_test.testProofModeIsNotGlobal` fails if the setting comes back.

Consequences for callers of `solve_and_proof`: the returned proof and assertions
belong to the private context, so they cannot be combined with expressions built in
Z3's default context.

## Why it was removed

With `z3-solver==5.3.3.0` and proof mode on, some quantified queries return `unknown`
("incomplete quantifiers") depending on the random seed and on what was solved
earlier in the process, where 5.3.2.0 and earlier answer `unsat` in milliseconds.
The library check then gave different results depending on machine, job count and
theory order.  With proof mode off the answers are stable.  The first bad Z3 commit is 88df9ce84 (PR #11348, `qsat` refuses proof-enabled goals), see
`docs/triage/z3_bisect.txt`.  Details and the
reproduction are in `docs/triage/z3_proof_regression.md`; the regression tests are
`testSolveSequence` and `testProofModeIsNotGlobal` in
`holpy/prover/tests/z3wrapper_test.py`.

## Supported versions

`pyproject.toml` requires `z3-solver>=4.12` with no upper bound.  CI (job `library`) runs the
library check with z3-solver 5.3.2.0 and with the newest release, and compares each result
with `docs/library_check.tsv` (generated with 5.3.2.0 on aarch64).  A theorem that goes from
`ok` to another status fails the job, except the Z3-brittle theorems listed in
`scripts/z3_brittle.txt`.

## Z3-brittle theorems

Z3 is incomplete for quantified queries (alternation such as `exists a. forall x. ...`): which
seed or term numbering a process gets decides whether it answers `unsat` or `unknown`, in every
release tested (4.13.4.0 to 5.3.3.0).  Two library theorems depended on this and were rewritten
so that no Z3 step has to find an existential witness: `set.nat_finite` (witness `n + x`) and
`realderivative.lhospital` (witness `d1`, as in the `f` case of the same proof).  The queries and
seed tables are in `docs/triage/z3_smtlib/`; `docs/triage/z3_library_queries.py` lists the fragile
queries of any theory.  `scripts/z3_brittle.txt` is the (currently empty) allow list for the CI
comparison; add a theorem to it only with evidence.  To regenerate the baseline, run
`python scripts/check_library.py --jobs 3 --out docs/library_check.tsv` with z3-solver 5.3.2.0.
